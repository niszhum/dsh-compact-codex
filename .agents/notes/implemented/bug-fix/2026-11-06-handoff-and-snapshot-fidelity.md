# Agent Note: 交接信息与自动快照的三处失真

Status: implemented

## 问题

换窗后的新窗口只能靠交接信息与账本接手工作，任何一处失真都会被当成事实。2026-11-06 的一次真实换窗（本仓库所在会话，第 2 窗口）暴露出三处：

**账本的层级被打平。** 记录正文允许换行，渲染主页时是整段插进列表项的，续行从第一列开始。那条自动快照记录的第二行「已由系统归档：」于是和「- **auto-snapshot**」并列，新窗口读起来像两个任务。根因是 `renderHome` 的 `clip` 只截断、不处理换行。

**自动快照把流程当进度，摘要还是结果首行。** 快照的用途是「钉住未记账的进度」，但它遍历全部工具结果，记账与换窗自己的结果也在其中——一条 `ledger_append` 的「已记录 #L1」和一次 `new_context` 的返回文案被归档成「这一段做过了」。摘要取结果首行，对 `run_code` 通常是一段装饰过的 stdout：拿 1444 条事件的真实 PTC 会话重放，旧口径给出的五条摘要是「1422 会话事件总数: 452 | tool/call: 30 seq=18 run_code …」「=== seq=80 原始调用代码 === …」这类碎片，新窗口读完不知道做了什么。

**文件工作集把脚本里的路径当成改过的文件。** PTC 模式下 `run_code` 不产生 `meta.diffs`，回退逻辑是「参数里出现 `xxx.write(` 就把附近的 `file_path` 字面量当写路径」。这个正则命中的是 `process.stdout.write(` 这类调用，于是夹具与脚本正文里的路径全被收进来：交接信息把 `src/fetch.js` 记成「最近被改动的文件」，而该文件从头到尾没被碰过。

## 决策

账本主页渲染对 `text`、`next_step`、`done_when` 与请求正文做续行缩进，缩进量对齐字段所在的层级（记录正文 6 空格、任务字段 4 空格、请求条目 2 空格）。

自动快照只归档真正的动作：工具名属于换窗与账本读写、或参数原文里出现 `tools.new_context(` / `tools.ledger_append(` 这类自指调用、或结果里带换窗成功文案的，整条跳过。摘要写「做了什么」——`工具名：参数摘要`；无法配对到调用时退回结果首行。未记账总数（门槛判据）仍按工具结果计，只是摘要条数可以少于它，差量在快照文本里以「（另有 N 个未记账结果未列出）」说明。

PTC 的写路径回退只认 SDK 写调用本身（`tools.write(`、`tools.edit(`、`tools.apply_patch(` 等），并且只在匹配位置向后 2000 字符的参数窗口里找 `file_path` / `path` / `filename`；`apply_patch` 另认补丁正文里的 `*** Update File:`。

## 曾考虑的替代方案

**把多行记录压成单行再渲染。** 否决。压平会吃掉「标题行 + 归档列表」这类二级结构，而模型自己写的 `text` 同样可能换行——在渲染端做缩进对两种来源都成立，在写入端压平只能管住代码自己生成的那一种。

**快照摘要保留结果首行，只把自指动作滤掉。** 否决。自指动作只占噪音的一小部分，真正的噪音来自 `run_code` 的 stdout 本身：真实会话里 257 次调用全是 `run_code`，结果首行几乎没有可读的「做了什么」。摘要换成工具名加参数之后，同样的五条变成「run_code：Inspect ptc.txt size and user dsh configs」「run_code：List user dsh home directory contents」。

**自指动作同时不进门槛计数。** 否决。门槛（`tailOf`）回答的是「记账之后还有多少工具结果没被覆盖」，这是覆盖边界问题，不是内容问题；把自指结果从计数里去掉会让门槛过早放行，而放行的代价正是「换窗后重做已完成步骤」。计数与展示分离：计数全算，摘要不列。

**PTC 写路径继续放宽到任意 `xxx.write(`。** 否决。宽松命中的典型是 `process.stdout.write(`，而它在 `run_code` 里几乎每次都会出现，等于把「回退」变成「把脚本里的所有路径都算上」。

**用括号配平解析出参数对象，只在对象内部找路径。** 否决。参数是任意 JavaScript，写配平器要处理字符串、模板、注释与转义，收益只是把窗口从 2000 字符收紧到「对象内部」。窗口法加 SDK 前缀已经能挡住实测到的误判。

## 后果

自动快照在「只剩自指动作」时不渲染归档列表，只留一句数量与回查说明。这一条让快照在纯记账/换窗的短窗口里显得更空，但它本来就不该有内容。

文件工作集在「全是 `run_code`、且没有 SDK 写调用」的会话里为空。这是诚实的结果，不是漏判：那些会话确实没通过工具写文件。旧启发式漏掉的写操作（把路径拼进变量再传、用 `node:fs` 直接写）依然漏，与 [交接信息的任务轨迹索引与账本完成判据](../architecture/2026-11-06-handoff-request-trail-and-done-when.md) 记的缺口一致，未纳入本轮。

两份记录的关系：本轮推翻了那份记录里「换窗前的自动快照改记工具结果首行」与「文件工作集回退到参数里认出的写路径（不设窗口）」两条，其余（六段结构、裁剪顺序、`done_when`、模型可见文本不放计量）不变。
